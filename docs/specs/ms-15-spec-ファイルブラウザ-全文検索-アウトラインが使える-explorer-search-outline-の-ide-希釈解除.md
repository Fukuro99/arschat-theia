# ms-15 SPEC: ファイルブラウザ・全文検索・アウトラインが使える (Explorer / Search / Outline の IDE 希釈解除)

## 背景・なぜこのMSが必要か

ArsChat は「チャット主役の Theia アプリ」として IDE らしい画面部品を希釈フィルタ (= IDE の見た目を隠す仕組み) で隠してきたが、ms-12 (Extensions ビューの復活) を経て「必要な IDE 機能には入口を戻す」方向に舵を切っている。次の一歩として、IDE の基本であるファイルブラウザ (Explorer)・ファイル全文検索 (Search)・コード構造表示 (Outline) の 3 ビューを整備する。

現状はこの 3 ビューとも希釈フィルタで完全に隠れており、ユーザーはフォルダの中身を見る・ファイルを探す・コードの構造を眺める手段を持たない。ms-13 (チャット内に AI がボタン等の操作 UI を描く機能) より先にこの MS をやる、ms-14 (独自拡張システム) は一旦保留、という順序はユーザー判断 (2026-07-19)。

## 解決すべき問題

| # | 問題 |
|---|---|
| 1 | Explorer / Search / Outline が希釈フィルタで隠れており、ファイルを見る・探す・構造を眺める動線が存在しない |
| 2 | 起動時の stale ビュー掃除 (= 前回レイアウトに残った IDE ビューの自動削除) が 3 ビューを削除対象にしており、復活後もレイアウト復元を壊し続ける |
| 3 | 永続レイアウトの罠 (ms-12 で実証済み): フィルタを外すだけでは、既存プロファイルのアクティビティバーにアイコンは現れない |
| 4 | ワークスペース (= 開くフォルダ) 未オープン時、Explorer は空表示でフォルダを開く案内が出ない (Theia OSS 既定には空状態の案内ボタンが無いことを調査で確認) |
| 5 | 希釈の期待値が 3 ファイル (stale 掃除 / M6 autotest / M12 autotest) に重複定義されており、復活時に全部の同期修正が要る |

## 設計方針 (判断軌跡)

### 1. 3 ビューとも Theia 純正をそのまま復活させる (Explorer だけでなく Search / Outline も一括)

- 理由: ユーザー判断 (2026-07-19)。「見る (Explorer)・探す (Search)・構造を掴む (Outline)」をセットで IDE 化する。実装は ms-12 で確立した同型手法の繰り返しで済み、独自 UI を作るより実装量・保守コストが圧倒的に小さい。
- 却下した代替案: Explorer のみの最小スコープ — 検証範囲は狭くなるが、同型作業を 3 回の MS に分けるオーバーヘッドの方が大きいと判断。

### 2. フォルダを開く動線は Theia 標準に乗る (手動で開く + 前回フォルダ自動復元)

- 理由: ユーザー判断 (2026-07-19)。調査で File メニューの「フォルダーを開く」(Open Folder) が希釈対象外で生きていること、前回ワークスペースの自動復元 (recentworkspace.json 方式) も無効化されずに機能することを確認済み。ArsChat 側の新規実装ゼロでこの動線が成立する。
- 空の Explorer に独自の「フォルダーを開く」案内 UI は今回作らない (問題 4 は認識した上でスコープ外)。既定フォルダの自動オープンも却下 — ユーザーの意図しないフォルダを勝手に開かない。

### 3. 希釈フィルタからのピンポイント除外方式を踏襲する

- 理由: ms-12 と同じ。フィルタ機構は維持し、FileNavigatorContribution / SearchInWorkspaceFrontendContribution / OutlineViewContribution の 3 クラスだけを除外リストから外す。SCM / Debug / Test / 純正チャットの希釈は維持され、影響範囲が最小になる。
- 除外で復活するのはコマンド・キーバインド・メニュー項目・アクティビティバーアイコン・ツールバー (調査で bind 型の全量を確認済み)。

### 4. 永続レイアウト補完 (ms-12 の復元 contribution) を 3 ビュー対応に一般化する

- 理由: ms-12 で実証した通り、既存プロファイルの永続レイアウトにはこれらのビューが含まれず (むしろ掃除が消し続けてきた)、フィルタ解除だけではアイコンが現れない。Explorer / Search は左パネル、Outline は右パネル (Theia 既定 rank 500) に、無ければ足す方式で補完する。activate はしない (チャットが主役のまま)。

### 5. チャット主役のレイアウト方針は変えない

- 理由: 調査で、ファイルをダブルクリックしてエディタを開いても実行時にチャットへ強制的にフォーカスが戻るロジックは無いことを確認済み。唯一の既存挙動「起動時にチャットを前面にする」はそのまま維持する — 再起動直後にエディタではなくチャットが前面に来るのは仕様と割り切る。

### 6. 検証は ARSCHAT_M15_AUTOTEST フラグ方式 + 期待値 3 箇所の同期修正

- 理由: ms-6 以来のフラグ式自動検証パターンの踏襲。希釈期待値の配列は stale 掃除・M6 autotest・M12 autotest に独立コピーが 3 つあることが調査で判明しており、'navigator' / 'explorer' / 'files' / 'search-in-workspace' / 'outline' を全箇所から同期して外す ('navigator' は現行 Theia の実 id に一致しない死んだパターンなのでこの機会に整理)。'scm' / 'debug' / 'test' / 'chat-view-widget' は残す。

## スコープ

### やる
- 希釈フィルタから Explorer / Search / Outline の 3 クラスを除外し、アイコン・メニュー・キーバインドを復活させる
- stale ビュー掃除と M6 / M12 autotest の期待値配列 (3 箇所) から対象パターンを同期除去
- 永続レイアウト補完を 3 ビュー対応に一般化 (左: Explorer・Search / 右: Outline)
- 実機確認: フォルダを開く → ツリー表示 → ダブルクリックで編集 → 全文検索 → アウトライン表示 → 再起動で前回フォルダとレイアウトが復元
- ARSCHAT_M15_AUTOTEST による自動検証
- BUILD_NOTES への実装メモ追記

### やらない (別MS or 後回し)
- 空の Explorer に出す独自「フォルダーを開く」案内 UI (需要が出たら別 MS)
- 既定フォルダの自動オープン
- チャット / AI とファイルブラウザの連動 (AI が触ったファイルの強調など)
- SCM / Debug / Test ビューの復活 (希釈維持)
- ms-14 (独自拡張システム) — ユーザー判断で保留中
- GitLens プラグインビューの希釈問題 (ms-11 からの既知の別課題、別タスク)

## 受入条件 (AI 推測 — 修正自由)

1. アクティビティバー (画面左端のアイコン列) に Explorer と Search のアイコンが表示され、クリックで開閉できる
2. File メニューの「フォルダーを開く」でフォルダを選ぶと、Explorer にファイルツリーが表示される
3. ツリーのファイルをダブルクリックするとエディタが開き、編集・保存ができる
4. アプリを再起動すると、前回のフォルダとレイアウトが自動復元される
5. Search ビューでキーワードを入力するとワークスペース全体の一致箇所が一覧され、クリックで該当行に飛べる
6. コードファイルを開くと Outline (右パネル) に関数・クラス等の構造が表示される
7. 他の希釈 (SCM / Debug / Test / 純正チャットの非表示、メニューバー File/Edit/View/Help のみ) は維持されている
8. ARSCHAT_M15_AUTOTEST で主要動線が自動検証され PASS する (GitLens 既知問題による FAIL は除く)

## 実装順序のヒント (AI 推測 — 修正自由)

1. 希釈フィルタ (arschat-ide-dilution.ts) から 3 クラスを除外 — 入口の本体
2. stale ビュー掃除 + M6 / M12 autotest の期待値配列を同期修正 — 1 と同時でないと再起動・検証が壊れる
3. 永続レイアウト補完の一般化 (ms-12 の arschat-extensions-view-restorer.ts を拡張 or 汎用化)
4. 実機確認 (フォルダ→編集→検索→アウトライン→再起動)
5. ARSCHAT_M15_AUTOTEST 追加
6. BUILD_NOTES 追記
