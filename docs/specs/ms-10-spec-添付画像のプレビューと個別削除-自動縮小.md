# ms-10 SPEC: 添付画像のプレビューと個別削除・自動縮小

> 2026-07-18 改訂: Sonnet 調査 (MS10_BRIEF.md) により、サムネイル一覧と個別削除は ms-4 (自前チャット UI) の時点で既に実装済みと判明。本 SPEC を実態に合わせて修正した。

## 背景・なぜこのMSが必要か

画像の添付 (貼り付け・ドラッグ&ドロップ・送信) は ms-4 で実装済み。当初このMSは「サムネイル表示・個別削除・縮小の 3 つが無い」前提で起票されたが、調査の結果、送信前のサムネイル一覧と × ボタンによる個別削除は ms-4 の実装に既に含まれていた (マイルストーン起票時に見落としていた)。

一方で「大きな画像の自動縮小」は本当に無い。原寸のままの大画像は通信量と AI への入力量 (トークン) を無駄に消費し、応答も遅くなる。また既存のサムネイル・個別削除には自動テストが無く、品質が担保されていない。

## 解決すべき問題

| # | 問題 | 状態 |
|---|---|---|
| 1 | 送信前のサムネイル一覧が無い → **実装済みと判明**。ただし自動テスト未整備 | テスト追加で品質担保 (e-52) |
| 2 | 個別削除が無い → **実装済みと判明**。同上 | テスト追加で品質担保 (e-53) |
| 3 | 大きな画像が原寸のまま送信され、通信量・トークン・応答時間を浪費する | 新規実装 (e-54) |

## 設計方針 (判断軌跡)

### 1. 既存のサムネイル・個別削除は変更せず、テストで固定する

- 理由: 実機で動いている実装に手を入れる理由が無い。挙動を Jest で固定し、今後の変更 (縮小の追加を含む) で壊れたら検知できる状態にすることが ms-10 での価値。

### 2. 大きな画像は送信時に自動で縮小する (確認ダイアログは出さない)

- 理由: 毎回ユーザーに縮小可否を聞くと添付のたびに摩擦が増える。AI の画像認識には実効的な解像度上限があり、それを超える原寸データを送っても認識精度は上がらない。長辺の上限 (目安 1568px) を超える画像だけブラウザ内で縮小して送る。
- サイズ計算 (アスペクト比維持で長辺を上限に丸める) は純粋関数に切り出す。理由: テスト実行環境 (jsdom) には canvas (ブラウザの描画機構) が無く、描画部分は単体テストできないため、テスト可能な計算部分と描画の副作用部分を分離する。
- アニメーション GIF は縮小対象から除外する。理由: canvas を通すと 1 フレームの静止画になり、情報が失われる。

### 3. 送信の体感速度を守る

- 理由: 縮小処理の完了を待ってから画面反映すると、送信ボタンを押してから添付行が消えるまでに遅延が生まれる。既存の「送信と同時に添付行が消える」体感を維持する順序 (画面クリアを縮小処理より先に行う) で実装する。

### 4. 移植元 ArsChat の縮小まわりは手本にしない

- 理由: 移植元は単一画像のみ対応で縮小処理自体が存在しない (ms-8 の IME と同様、移植元にも欠陥がある)。プレビュー UI の見た目は参考にできるが、既に現行実装があるため流用の必要も無い。

## スコープ

### やる
- 長辺上限を超える画像の送信時自動縮小 (新規実装)
- 既存のサムネイル一覧・個別削除の Jest テスト追加 (品質固定)
- 実機確認 (貼り付け・個別削除・縮小の 3 動作)

### やらない (別MS or 後回し)
- サムネイル・個別削除の UI 変更 (既存実装のまま)
- サムネイルのクリック拡大表示 (lightbox)
- 画像以外のファイル添付 (PDF 等)
- 過去メッセージに含まれる画像の表示挙動の変更
- EXIF の回転補正・位置情報除去などの高度な画像処理

## 受入条件

1. 既存挙動のテスト固定: 貼り付け/ドラッグ&ドロップでサムネイルが並ぶ・× で 1 枚だけ外れる・添付 0 件で行が消える、が Jest で検証されている
2. 長辺が上限超の画像は送信時に自動縮小され、縮小後データが AI に渡る (上限以下と GIF は無加工)
3. 縮小のサイズ計算が純粋関数として切り出され、Jest でフルテストされている
4. 送信ボタン押下と同時に添付行が消える既存の体感が維持されている
5. Jest 全 green (既存 77 件 + 追加分)
6. 実機で貼り付け・個別削除・縮小を確認済み

## 実装順序のヒント

1. 縮小のサイズ計算関数 + 描画ラッパー (e-54) — MS10_BRIEF.md の方針に従う
2. 既存サムネイル・個別削除のテスト追加 (e-52, e-53)
3. Codex レビュー → 実機確認 → BUILD_NOTES 追記 (e-55)
