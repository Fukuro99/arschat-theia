# ms-12 SPEC: VS Code 拡張を検索してワンクリックで入れられる (Open VSX マーケットプレイス統合)

## 背景・なぜこのMSが必要か

ArsChat は「チャットアプリに見える Theia アプリ」として作られており、IDE 由来の画面部品は希釈フィルタ (= IDE らしい見た目を隠す仕組み、arschat-ide-dilution.ts) で隠している。一方、VS Code 拡張を動かす基盤 (@theia/plugin-ext / @theia/vsx-registry) は既に導入済みで、PoC-3 の自動検証では GitLens や ESLint などの実拡張が実際に動くことまで確認できている。

問題は、拡張の検索・設置画面 (Extensions ビュー) がその希釈フィルタで完全に隠れていること。つまり「拡張は動くのに、ユーザーが拡張を探して入れる入口がゼロ」の状態。放置すると、テーマや言語サポートなどユーザーごとに欲しい拡張を入れる手段がなく、開発者が plugins フォルダへ手作業で配置するしかない。

この MS は新機能をゼロから作るのではなく、**既に動いている拡張基盤に、ユーザーが自分で使える入口を付ける** MS である。

## 解決すべき問題

| # | 問題 |
|---|---|
| 1 | Extensions ビューが希釈フィルタで隠れており、拡張を検索・設置する動線が存在しない |
| 2 | 起動時の stale ビュー掃除 (= 前回レイアウトに残った IDE ビューの自動削除、arschat-stale-ide-view-cleanup.ts) が 'vsx' ビューを削除対象にしているため、Extensions ビューを開いたまま再起動するとレイアウト復元が壊れる |
| 3 | 「検索 → ワンクリック設置 → 再起動後も拡張が有効」という一連のユーザー体験が未検証 |

## 設計方針 (判断軌跡)

### 1. 純正 Extensions ビューをアクティビティバー (= 画面左端のアイコン列) に復活させる

- 理由: ユーザー判断 (2026-07-19)。実装量が最小で、検索・設置・更新・削除が Theia 純正機能のまま使える。IDE らしい見た目が一部戻るが、拡張管理は「道具箱」的な画面なのでチャットアプリの世界観を大きくは壊さない、という判断。
- 却下した代替案: (a) ms-11 のターミナルと同型のヘッダー専用ボタン方式 — 希釈は保てるが開閉配線の実装が増える。(b) チャット風の独自 UI — 見た目の統一感は最高だが検索・設置・更新・削除の自前実装が必要で、この MS の価値 (入口を付ける) に対して過剰。

### 2. 希釈フィルタからのピンポイント除外方式で復活させる

- 理由: 希釈フィルタの仕組み自体は維持し、VSXExtensionsContribution (Extensions ビューを提供するクラス) だけを除外リストから外す。SCM / Debug / Search / Explorer / Outline / 純正チャットなど他の希釈は今まで通り維持され、影響範囲が最小になる。

### 3. 拡張の配布元は Open VSX (open-vsx.org) の既定設定をそのまま使う

- 理由: Theia の既定レジストリ (= 拡張の配布元サーバー) が Open VSX であり、MS タイトルの通り。Microsoft Marketplace はライセンス上 VS Code 以外から使えないため対象外。配布元の切り替え UI は本 MS ではやらない。

### 4. 自動検証は ARSCHAT_M12_AUTOTEST フラグ方式を踏襲する

- 理由: ms-6 (見た目の希釈) / ms-10 (画像添付) / ms-11 (ターミナル開閉) で確立した「環境変数フラグで起動時に自動検証を走らせ、スクリーンショットとログで PASS/FAIL を残す」パターンをそのまま使う。検証方式を統一しておくと退行検知の運用が楽になる。

## スコープ

### やる
- 希釈フィルタから Extensions ビューを除外し、アクティビティバーにアイコンを復活させる (View メニューの開閉項目も含む)
- 起動時の stale ビュー掃除から vsx 系を除外し、Extensions ビューを開いたままの再起動でもレイアウトが復元されるようにする
- 「検索 → ワンクリック設置 → 拡張が有効化 → 再起動後も有効」の実機確認
- ARSCHAT_M12_AUTOTEST による自動検証
- BUILD_NOTES への実装メモ追記

### やらない (別MS or 後回し)
- チャット風の独自拡張管理 UI (純正ビューで十分と判断した時点で対象外)
- 拡張の配布元切り替え UI・社内レジストリ対応 (需要が出たら別 MS)
- おすすめ拡張リストや初期バンドル拡張の見直し (別 MS)
- Microsoft Marketplace 対応 (ライセンス上不可)

## 受入条件 (AI 推測 — 修正自由)

1. アクティビティバーに Extensions アイコンが表示され、クリックで Extensions ビューが開く
2. 検索欄にキーワード (例: "theme") を入力すると Open VSX の検索結果が一覧表示される
3. 検索結果の Install ボタン 1 クリックで拡張が設置され、その場で有効化される
4. アプリを再起動しても、設置した拡張が有効なまま残っている
5. 設置済み拡張のアンインストール・更新が純正 UI から実行できる
6. 他の希釈 (SCM / Debug / Search / Explorer / Outline / 純正チャットビューの非表示) は維持されている
7. Extensions ビューを開いたまま再起動してもレイアウト復元が壊れない
8. ARSCHAT_M12_AUTOTEST で上記の主要動線が自動検証され PASS する

## 実装順序のヒント (AI 推測 — 修正自由)

1. 希釈フィルタ (arschat-ide-dilution.ts) の MENU_FILTERED / ACTIVITY_BAR_FILTERED から VSXExtensionsContribution を除外 — これが入口の本体
2. stale ビュー掃除 (arschat-stale-ide-view-cleanup.ts) の削除対象から vsx 系を除外 — 1 と同時にやらないと再起動で消える
3. 実機確認: 検索 → 設置 → 有効化 → 再起動後も有効、を通しで確認
4. ARSCHAT_M12_AUTOTEST の自動検証を追加
5. BUILD_NOTES へ実装メモ・確認結果を追記
