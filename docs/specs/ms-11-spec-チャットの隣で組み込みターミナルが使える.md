# ms-11 SPEC: チャットの隣で組み込みターミナルが使える

## 背景・なぜこのMSが必要か

ArsChat は Theia (= オープンソースの IDE 基盤) をベースにしたチャット専用アプリで、IDE らしい画面要素は「希釈フィルタ」(= メニューやアイコンをアプリ起動前に取り除く仕組み) で隠している。しかし AI との会話中に、提案されたコマンドを手元で試したい・作業フォルダの中身をさっと確認したい場面ではターミナルが欲しくなる。

コード調査の結果、ターミナル機能 (`@theia/terminal`) は依存としてすべてのアプリに入ったまま眠っており、ターミナルを開くコマンドやキーボードショートカットは今も生きている。隠されているのは「Terminal」トップメニューという入口だけだった。つまり ms-11 は大掛かりな機能追加ではなく、眠っている機能に「チャットアプリらしい入口と置き場所」を与えて再露出する仕事である。放置すると、ユーザーはコマンド確認のたびに別のターミナルアプリへ行き来することになり、チャットと作業の分断が続く。

## 解決すべき問題

| # | 問題 |
|---|---|
| 1 | ターミナルを開く入口が無い (メニュー希釈で唯一の入口が消えており、コマンドパレット経由は知る人ぞ知る状態) |
| 2 | 開いたときの置き場所・閉じて再度開く動線が未設計 (画面下部のパネルは現在どの機能にも使われていない) |
| 3 | 再露出が既存の希釈方針や、再起動時のレイアウト復元 (前回の画面配置を覚えて復元する仕組み) と矛盾しないことが未確認 |

## 設計方針 (判断軌跡)

### 1. 配置は Theia 標準の下パネル (画面下部)

- 理由: 実装工数が最小で、Theia のターミナル既定動作をそのまま使える。ArsChat では下パネルが未使用なので既存ビューと干渉しない。「チャットの隣」の本質は左右に並ぶことではなく「チャットと同時に見えること」だと判断した (ユーザー確認済み)。
- 却下案: 右パネル / メイン画面の左右分割 — 配置を自前制御する実装が必要になり、既存のレイアウト清掃処理やチャット強制表示のロジックとの整合確認が増える。

### 2. 入口は ArsChat 専用ボタン (Terminal メニューは隠したまま)

- 理由: チャットアプリらしい見た目を守るため、メニューバーに IDE らしい項目を復活させない。専用ボタンなら置き場所も文言も ArsChat 側で決められる (ユーザー確認済み)。
- 却下案: Terminal メニューの再露出 — フィルタから 1 行外すだけで最小工数だが、トップメニューが IDE 寄りの見た目に戻る。

### 3. 希釈フィルタは現状維持 (フィルタを緩めない)

- 理由: ターミナルのコマンド自体は既に生きているので、フィルタを緩めなくても専用ボタンから既存コマンドを呼べば開ける。「隠す仕組み」と「開く入口」を分離しておくことで、希釈の一貫性が守られる。

### 4. Theia 本体 (node_modules) は無改変

- 理由: これまでの MS すべてで守ってきた原則。本体改変はバージョン更新のたびに壊れる借金になる。

## スコープ

### やる

- ターミナルを開閉する専用ボタン (チャット画面またはツールバー上)
- 下パネルへの表示・閉じる・再度開くの一連の動線
- 再起動後のレイアウト復元と希釈の見た目が壊れないことの確認
- 自動検証 (過去 MS の ARSCHAT_MX_AUTOTEST と同型) と実機確認

### やらない (別MS or 後回し)

- AI とターミナルの連携 (AI がコマンドを流し込む・出力を読む等) — 価値は大きいが別 MS で扱う
- 複数ターミナルの管理 UI・画面分割・シェルのプロファイル設定
- 右パネルやメイン分割などの独自レイアウト
- Terminal トップメニューの再露出

## 受入条件

1. チャット画面から 1 クリック (専用ボタン) でターミナルが開く
2. ターミナルは画面下部のパネルに開き、チャットと同時に見える
3. ターミナル上でコマンド (例: `dir` / `echo`) を実行すると出力が表示される
4. ターミナルを閉じられ、もう一度ボタンで開き直せる
5. メニューバー等に IDE 由来の要素が復活していない (希釈の見た目が維持されている)
6. アプリを再起動しても画面が壊れない (ターミナルの復元有無どちらの挙動でも破綻しない)
7. 自動検証でターミナルの開閉が確認できる

## 実装順序のヒント

1. 専用ボタンの置き場所を決めて UI を実装する
2. ボタンから Theia の既存ターミナルコマンドを呼び、開閉トグルとして接続する
3. 再起動 (レイアウト復元) と希釈の見た目の回帰確認
4. 自動検証の追加 + 実機確認 + BUILD_NOTES への実装メモ追記

作業分担 (ユーザー指定の方針): 事前調査は Sonnet のサブエージェント、実装とレビューは Codex (別セッション)、設計判断が絡む複雑なタスクは Opus に委譲する。
