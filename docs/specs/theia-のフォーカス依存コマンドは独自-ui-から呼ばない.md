# Theia のフォーカス依存コマンドは独自 UI から呼ばない

## 原則

ArsChat の独自 UI (チャットヘッダーのボタン等) から Theia 標準のコマンドを呼ぶとき、そのコマンドが **「どのウィジェットがフォーカスを持っているか (activeWidget)」や「タブが選択されているか」を暗黙の前提にしていないか** を必ず確認する。前提にしている場合、そのコマンドへの委譲は成立しないので、フォーカス・タブ選択に依存しない分岐を ArsChat 側で自前実装する。

## なぜ (ms-11 で実際に踏んだ 2 つのバグ)

ms-11 (チャットの隣で組み込みターミナルが使える) で、ヘッダーの「ターミナル」ボタンから Theia 標準のトグルコマンド `workbench.action.terminal.toggleTerminal` に全委譲したところ、机上レビュー 2 巡では見つからず、実機の自動検証で初めて 2 つのバグが出た:

1. **永遠に閉じられない**: Theia のトグルは「表示中のターミナルが activeWidget のときだけ畳む」仕様。ボタンをクリックした瞬間フォーカスはチャット側へ移るので、畳む分岐に決して入らず、毎回ターミナルの再アクティブ化だけが起きる。Theia のトグルはターミナル内で押すショートカット (Ctrl+`) 前提の設計だった。
2. **開いてもパネルが空に見える**: 再起動でレイアウト復元されたターミナルはタブ未選択のままパネルに入っている。Theia のトグルの展開分岐は `widget.activate()` しか呼ばず、タブ選択 (`selectWidget`) を保証しないため、パネルは展開されても中身が表示されない。

どちらも「Theia 標準コマンドは、その機能自身の UI 文脈 (フォーカスがその機能にある状態) で呼ばれる前提で書かれている」ことが根本原因。ArsChat は Theia の機能を独自 UI から再露出するアプリなので、この前提は今後もあらゆる再露出で崩れる。

## どう適用するか

- Theia コマンドへ委譲する前に、node_modules の該当実装を読み、`shell.activeWidget` / `currentTitle` / `isVisible` 等のフォーカス・選択状態への参照が無いか確認する
- 参照がある場合: 状態判定 (`shell.isExpanded` / `widget.isVisible` 等) と操作 (`collapsePanel` / `expandPanel` + `bottomPanel.activateWidget` 等) を ArsChat 側で明示的に行う。委譲してよいのは「フォーカス状態と無関係な部分」(例: ms-11 ではターミナルの新規作成のみ委譲) に限る
- 机上レビューではこの種のバグは検出しにくい。実機の自動検証 (ARSCHAT_MXX_AUTOTEST) を UI 導線ごとに用意し、実際のフォーカス遷移込みで確認する
